🚀 Quick Start — เริ่มต้นใช้งาน
เริ่มโปรเจกต์ใหม่ตั้งแต่ศูนย์ถึง report ใน 7 ขั้นตอน
1️⃣
สร้าง Project ใน Hub
ไปที่ Projects → Add Project → กรอก Name, Base URL, Type = full-pipeline → Click Copy Scaffold
Hub จะสร้างโฟลเดอร์พร้อม template ทั้งหมดให้อัตโนมัติ
2️⃣
วาง Requirements
วางไฟล์ requirement (.md / .txt / Figma export) ใน requirements/
หรือพิมพ์ /write-req [feature name] ใน Claude Code เพื่อสร้างไฟล์
3️⃣
รัน BA Agent → สร้าง TCM
พิมพ์ /ba-agent requirements/myfile.md
Agent วิเคราะห์ requirements แล้วสร้าง input/[Project]_TestCase.xlsx
4️⃣
ตรวจ TCM ก่อนรัน Test
พิมพ์ /excel-review-agent เพื่อตรวจคุณภาพ TCM
ถ้ามี 🔴 Critical Issues → แก้ก่อน ระบบจะ block ไม่ให้รัน test
5️⃣
รัน Playwright Tests
พิมพ์ /test (ทุก test บน UAT) หรือ /test-tag @smoke (เฉพาะ smoke)
ระบบ pre-check ว่า BASE_URL เข้าถึงได้ก่อนรันเสมอ
6️⃣
ขอ Release Approval
พิมพ์ /approve-release — ระบบตรวจ 8 gate criteria อัตโนมัติ
สร้าง sign-off checklist ใน docs/reviews/ พร้อมส่ง Slack notification
7️⃣
Generate Report และส่งทีม
พิมพ์ /report สร้าง Word report → /inject ใส่ screenshot → /report-send ส่ง Email + Slack

🌅 Daily Route — รอบทำงานต่อวัน
QA cycle ที่แนะนำ — ทำตาม route นี้ทุกเช้าจะรู้สถานะระบบทั้งหมดใน 5–10 นาที

☀️ เช้า (08:00–09:00) — ตรวจผลรอบกลางคืน

  1. เปิด Dashboard → ดู scheduled run ของเมื่อคืน (default 02:00 บาง project) — pass/fail rate ของ @smoke หรือ slow and statemod
  2. ถ้ามีสีแดง → Pipeline → Run History → เปิด log → ระบุ root cause
    สำหรับ desktop-automation: ใช้ /test-triage ใน Claude Code
  3. Bug Tracker → ดู Critical / High ที่ Open — อัปเดต assignee + status

☕ ระหว่างวัน — Develop + Iterate

  1. /write-req <slug> <input> → requirements/<slug>.md (resolve open questions) → /generate-spec <slug> สร้าง test file
  2. ก่อน commit → python scripts/pre_commit_check.py (pytest collect + lint + spec↔test pairing)
  3. Push → GitHub Actions รัน default suite อัตโนมัติ → ผลขึ้น hub ถ้า set HUB_URL
  4. ระหว่าง dev → Pipeline → Stage 5 ▶ Run ทดสอบสด

🌙 ก่อนกลับ (17:00–18:00) — Schedule + Release

  1. Slow test ใหม่ → Schedule tab → + Add → daily off-peak (เช่น 02:00) ด้วย tag slow and statemod
  2. ถ้าจะ release → Release Gate → ตรวจทุก criterion เป็น GO
  3. License monitor (desktop-automation): python scripts/check_license_expiry.py → warn ที่ ≤ 30 วัน

📅 รายสัปดาห์ — Audit + Cleanup

  1. /coverage-gap ใน Claude Code → audit requirement ↔ test pairing + TCID coverage
  2. /hub-structure-check → จับ tech debt / drift ของ hub เอง
  3. python scripts/cleanup_logs.py → prune logs (7d) + screenshots (30d)
💡 เป้าหมาย: สถานะระบบทั้งหมดต้อง green ก่อนคืนนี้ → schedule วิ่งคืนต่อไป → เช้าได้เห็นสีแดง/เขียวก่อนเริ่มงาน → loop กลับ

🤖 AI Agents — ใครทำอะไร

BA Agent
Business Analyst — วิเคราะห์ requirements
เรียกใช้เมื่อ: มี requirements ใหม่ หรือต้องการแปลง Figma/doc → TCM
Input: .md / .txt / Figma image / User Story
Output: logs/ba_output_YYYYMMDD.json + สร้าง input/*.xlsx
Command: /ba-agent [file]
🧪
QA Agent
QA Specialist — 6 modes
Modes:
• TCM_GENERATE — สร้าง Excel TCM จาก BA Output
• COVERAGE_CHECK — ตรวจว่า spec ครอบ TCM ครบไหม
• RISK_ANALYSIS — จัดลำดับ test cases ตามความเสี่ยง
• TEST_DATA — ออกแบบ test data (boundary, equivalence) + สร้าง test-data.json
• BUG_REPORT — สร้าง bug report จาก Playwright failure
• TRACEABILITY — สร้าง Requirement ↔ TC ↔ Result matrix

Playwright Agent
Test Automation Engineer
เรียกใช้เมื่อ: เขียน/รัน/แก้ Playwright spec
Tags ที่รองรับ: @smoke · @e2e · @regression · @visual
Flaky detection: test ที่ pass หลัง retry = flaky — ถ้า ≥ 3 runs = blocker
ENV support: TEST_ENV=uat|prod ส่งผ่าน env var
